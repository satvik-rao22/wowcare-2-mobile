================================================================================
CRITICAL LOGIN FIX - FCM 401 Unauthorized Breaking All Login
================================================================================

ROOT CAUSE
──────────────────────────────────────────────────────────────────────────────

SessionExpiredInterceptor is logging out users when FCM APIs return 401.

Why:
1. FCM paths NOT in _shouldIgnorePath() ignore list
2. 401 on /api/v1/notification/fcm/register → triggers session expiry
3. performLogoutDueToExpiredSession() called
4. User logged out immediately after successful login
5. Login flow breaks

AFFECTED
──────────────────────────────────────────────────────────────────────────────
- Guardian login ❌ BROKEN
- Staff login ❌ BROKEN
- Admin login ❌ BROKEN
- Kiosk login (may also be affected)

   ✅ Added FCM paths to ignore list

   ✅ FCM 401 errors now do NOT trigger logout

NEW BEHAVIOR
──────────────────────────────────────────────────────────────────────────────

BEFORE:
User logs in
→ FCM API returns 401
→ Interceptor catches 401
→ Logout triggered
→ Login fails ❌

AFTER:
User logs in
→ FCM API returns 401
→ Interceptor sees /notification path
→ Error ignored (non-fatal)
→ FCM service catches error and logs it
→ Auth cubit catches error and logs it
→ Login completes successfully ✅
→ User navigated correctly ✅

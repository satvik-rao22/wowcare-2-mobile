ROOT CAUSE:
The app is 223 MB because:
1. x86_64 architecture (65 MB) - Completely unnecessary in release APK
2. FFmpeg full codec library (25-35 MB) - May not be fully utilized
3. Dart/Flutter runtime (58 MB) - Baseline, hard to reduce further
4. Assets (23 MB) - Reasonable, can be optimized

BIGGEST WINS:
1. Remove x86_64: -65 MB (5 minutes, zero risk)
2. Replace/remove FFmpeg: -15 to -35 MB (depends on usage)
3. Optimize assets: -5 to -10 MB (30-60 minutes)

LOW-HANGING FRUIT:
- Fix ABI filtering (immediate, safe, -65 MB)
- Enable proper build flags (immediate, safe, -3 MB)

CONDITIONAL OPTIMIZATIONS:
- Analyze FFmpeg usage (must understand first)
- Asset optimization (nice to have, low risk)
- Dependency cleanup (low impact, -2 to -5 MB)

HIGH-RISK OPTIMIZATIONS:
- Drop armeabi-v7a (loses 32-bit support, -36 MB)
- Remove PDF library (if not used, -8 to -10 MB)

QUICK REFERENCE COMMANDS

Check current APK size:
ls -lh build/app/outputs/apk/release/app-release.apk

flutter build apk --release --obfuscate --split-debug-info=build/app/profiles --tree-shake-icons

cd /tmp && unzip -o ~/path/to/app-release.apk > /dev/null 2>&1 && du -sh lib/ assets/ classes*.dex

Install on device:
adb install -r build/app/outputs/apk/release/app-release.apk

Clean and rebuild:
flutter clean && flutter pub get && flutter build apk --release

Convert PNG to WebP:
find assets/ -name "*.png" -type f ! -name "*.9.png" | while read f; do cwebp -q 85 "$f" -o "${f%.png}.webp"; done
